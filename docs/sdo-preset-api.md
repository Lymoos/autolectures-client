# Пресеты ссылок на курсы СДО — что нужно на сервере

Клиент уже умеет работать с этим API: ниже точное описание того, что он шлёт и
что ожидает получить. Всё остальное (хранилище, права) — на стороне сервера.

## Зачем

Клиент ищет ссылку на лекцию в СДО МИРЭА: открывает страницу курса, находит
раздел «Вебинары», выбирает строку своей группы и жмёт «Подключиться». Чтобы это
заработало, для каждого предмета нужно один раз указать адрес страницы курса.

Делать это каждому студенту вручную бессмысленно: у одной группы предметы общие.
Поэтому староста-администратор собирает набор ссылок у себя, сохраняет его как
**пресет группы**, а всем остальным в этой группе он приезжает с сервера
автоматически.

## Модель данных

```
SdoPreset
  group       string             — код группы в верхнем регистре, например "ИВБО-21-23"
  links       map[string]string  — ключ предмета → URL страницы курса
  updated_at  timestamp
  updated_by  user_id            — кто последний раз сохранил
```

Первичный ключ — `group`. На группу хранится **один** пресет, сохранение
перезаписывает его целиком (не merge).

### Про ключ предмета

Ключ — не название пары из расписания, а его нормализованная форма. Нормализацию
делает клиент (`internal/sdo.SubjectKey`), сервер её **не повторяет** и ключи не
интерпретирует — просто хранит строки как есть.

Как это выглядит: «ЛК Управление информационно-технологическими проектами» и
«ПР Управление информационно-технологическими проектами» дают один ключ
`управление информационно технологическими проектами` — то есть у лекций и
практик одного предмета ссылка общая.

Ограничения, которые стоит проверять:

- ключ: 1–200 символов, непустой после trim;
- значение: валидный `http://` или `https://` URL, до 500 символов;
- количество ключей в одном пресете: до 100;
- размер тела запроса: до 64 КБ.

## Эндпоинты

Все три требуют обычной авторизации по `Authorization: Bearer <access_token>` —
той же, что и `/api/v1/sync/*`.

### GET /api/v1/sdo/preset?group=ИВБО-21-23

Отдаёт пресет группы. Доступен **любому авторизованному пользователю** — читать
может вся группа (и, если не хочется усложнять, вообще любой авторизованный:
данные не секретные, это публичные адреса курсов).

```json
200 OK
{
  "group": "ИВБО-21-23",
  "links": {
    "управление информационно технологическими проектами": "https://online-edu.mirea.ru/course/view.php?id=3951",
    "проектирование клиент серверных систем": "https://online-edu.mirea.ru/course/view.php?id=4102"
  },
  "updated_at": "2026-09-07T20:15:00Z",
  "updated_by": "lymoos"
}
```

- `404` — пресета для группы нет. Клиент это обрабатывает штатно: чистит
  локальную копию и сообщает «для группы X пресета пока нет».
- `401` — истёк токен, клиент промолчит.

Параметр `group` сравнивать без учёта регистра, обрезая пробелы.

### PUT /api/v1/sdo/preset

Сохраняет (создаёт или перезаписывает) пресет. **Только для администратора.**

```json
{
  "group": "ИВБО-21-23",
  "links": { "ключ предмета": "https://online-edu.mirea.ru/course/view.php?id=3951" }
}
```

Ответ `200 OK` с телом как у GET (или пустой объект — клиент тело не читает).

Ошибки: `403` если пользователь не администратор, `400` при невалидных данных.
Текст причины лучше класть в поле `detail` — клиент показывает его пользователю
как есть.

### DELETE /api/v1/sdo/preset?group=ИВБО-21-23

Удаляет пресет группы. **Только для администратора.** `200` или `404` —
клиент оба ответа считает успехом.

## Права

Сейчас клиент считает администратором пользователя с логином `lymoos` — это
временно и нужно только для того, чтобы не показывать кнопки остальным.
Настоящую проверку должен делать сервер.

Предлагаю добавить пользователю флаг роли и отдавать его в `/api/v1/auth/me`:

```json
{ "login": "lymoos", "role": "admin" }
```

Тогда клиент перестанет опираться на логин и будет спрашивать роль у сервера.
Поле назвать можно как угодно (`role`, `is_admin`), главное — сообщи как, я
подхвачу его в клиенте одной правкой.

Пока роли нет, на PUT и DELETE достаточно проверки «логин == lymoos», но
сделать это **обязательно на сервере**: клиентская проверка защищает только от
случайного нажатия, но не от прямого запроса.

## Поведение клиента (чтобы совпало с ожиданиями)

- Пресет запрашивается при входе в аккаунт, при смене группы и по кнопке
  «Обновить» в окне курса.
- Полученный пресет хранится локально и переживает перезапуск: если сервер
  недоступен, ссылки продолжают работать.
- Своя ссылка, вписанная вручную, **всегда важнее** пресета. Пресет — значение
  по умолчанию для тех предметов, где своей ссылки нет.
- Сохранение пресета отправляет только **свои** ссылки администратора
  (не объединённые с ранее полученным пресетом), поэтому сервер должен
  перезаписывать набор целиком.
- Клиент нигде не показывает чужие пресеты и не запрашивает пресеты других
  групп — только своей.

## Что не нужно

- Версионирования и истории изменений не требуется.
- Слияния пресетов от нескольких администраторов не требуется — последний
  сохранивший перезаписывает.
- Синхронизации через WebSocket не нужно: клиент забирает пресет по HTTP в
  нужные моменты.
