# Автолекции — клиент

Один exe без установки. Интерфейс и трансляция крутятся во встроенном Edge (WebView2), поэтому видео MTS-Link играет без плясок с кодеками. Если WebView2 Runtime вдруг нет, клиент сам его докачает.

## Сборка

Нужен Go 1.23+:

```powershell
.\build.ps1                  # dist\autolectures.exe
.\build.ps1 -Release -Version 2.0.1
```

## Релиз

Обычный путь — пулл-реквест в `main`. После вливания workflow `release on merge` сам поднимает версию, ставит тег, собирает exe и публикует релиз; описание пулл-реквеста целиком становится описанием релиза, а первые 200 символов клиент показывает в уведомлении об обновлении. Значит, описание надо писать по-человечески: что изменилось для пользователя, а не список коммитов.

Как выбирается версия (берётся последний тег `v*` и увеличивается):

| Что в пулл-реквесте | Пример | Из 1.0.3 получится |
| --- | --- | --- |
| по умолчанию | «Починил мигание окна» | 1.0.4 |
| метка `release:minor` или заголовок с `feat:` | `feat: экран загрузки` | 1.1.0 |
| метка `release:major` или `!` в заголовке | `feat!: новый протокол` | 2.0.0 |
| метка `release:patch` | — | 1.0.4 |
| метка `no-release` | правка README | релиза не будет |

Версия зашивается в exe через `-X main.Version`, поэтому `main.go` править не нужно — константа там нужна только для локальных сборок.

Ручной путь остался: пуш тега `v*` запускает workflow `release`, который собирает и выкладывает exe без описания.

## Данные

`%LOCALAPPDATA%\Autolectures\` — config.json, профиль браузера, logs\app.log.

Токен аккаунта и пароль почты в config.json запечатаны DPAPI: расшифровать их может только та же учётная запись Windows на том же ПК. Скопированный на другую машину config.json приведёт к гостевому режиму, а не к чужому входу. Новый exe рядом со старым каталогом данных, наоборот, подхватит сохранённый вход — это не баг, а сессия; сбросить её можно кнопкой «Выйти из аккаунта» или удалением каталога.

## Администратор

Аккаунт `lymoos` считается админским: в «Параметры» (шестерёнка в панели заголовка) появляется блок со служебными действиями.

- **Пройти обучение заново** — сбрасывает отметку об обучении и сразу запускает тур.
- **Снести все данные и перезапустить** (в два клика) — клиент стартует сам себя с ключом `--reset <pid>`, новый процесс дожидается выхода старого, удаляет `config.json`, профиль браузера и каталог обновлений, после чего поднимается как после первой установки: гость, пустое расписание, экран подготовки и обучение. Журнал не трогается.

Тот же сброс можно сделать руками: `autolectures.exe --reset 0`.

`autolectures.exe --smoke` — проверочный запуск: поднять всё и выйти.
